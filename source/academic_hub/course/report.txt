3. PRINCIPLES APPLIED
---------------------
Single Responsibility Principle (SRP, SOLID "S")
  - views.py split into one module per feature: courses, roster, posts,
    materials, qa.
  - Business rules moved out of HTTP views into services:
      group_services.py : create group, public join, join requests,
                          invitations, seat reservation, kick/transfer,
                          cancelling competing invites/requests
      qa.py             : Q&A permission rules and serializers
  - Views now only read the request and build the response.

Dependency Inversion Principle (DIP, SOLID "D")
  - group_views.py used to import payload() from views.py (one view module
    depending on another). Both now depend on a shared module, responses.py.
  - Views depend on service functions and on exceptions (GroupRuleError,
    GroupForbidden, QAError), not on how each rule is implemented.

Open/Closed Principle (OCP, SOLID "O")
  - group_member_action uses a dispatch table (SELF_ACTIONS / HEAD_ACTIONS)
    instead of an if/elif chain. A new action is added by adding an entry,
    without editing the existing branches.

DRY (Don't Repeat Yourself) and removing code clones (Lec #12, Code Clones)
  - Exact clone: the "if API return JSON, else flash a message and redirect"
    branch appeared 86 times (34 in views.py, 52 in group_views.py). It is
    now respond() / fail() in responses.py, plus one rule_errors decorator
    for group views. The copies is_api / _is_api were merged into one.
  - Near-miss clones:
      topic selection (3 copies)              -> resolve_topic()
      attachment-to-material loop (2 copies)  -> attach_uploads()
      post owner check (4 copies)             -> can_modify_post()
      lock + fetch + archived check (9 Q&A
      endpoints)                              -> locked_question/locked_answer()
      "already in a group" / "no free seat" /
      lock work+group (5 group endpoints)     -> _require_no_group(),
                                                 _no_free_seat(), _lock()
      accept invitation / accept join request -> _accept_into()
      "not staff and not superuser" check     -> is_student_user()
  - Semantic clones: the Q&A permission rules were written twice, once for the
    JSON can_* flags and again inside each endpoint. Both now use the same
    functions in qa.py.
  - Tests: sign_in/url/upload were copied into each test class. They are now
    one CourseClientMixin in tests/helpers.py.

KISS (Keep It Simple) / simplify conditionals
  - Long views split into small helpers, e.g. group_work_detail (CC 36) ->
    describe_group, _viewer_status, _join_options, described_groups,
    group_data; edit_post -> save_post_edit, render_post_editor.
  - Errors are raised as exceptions and turned into a response in one place,
    replacing a return-error check after every step.

Readability / documentation (code quality dimensions 1 and 10)
  - Module and function docstrings explain WHY, e.g. why a pending invitation
    counts as a free seat for its invitee.
  - Type hints on the new shared helpers (PEP 484).
  - Unused imports removed, e.g. "from django.http import request", which
    shadowed the request parameter.

Testability (code quality dimension 5)
  - Rules in group_services.py / qa.py are plain functions that can be tested
    without going through HTTP.

9. BUG FIXES AFTER REFACTORING (924574f)
----------------------------------------
Done as a separate commit, so the refactoring commits stay behaviour-
preserving. Every fix comes with tests.

UI fixes (templates only)
  - Edit class page: "Delete class" showed for active classes. It now
    appears only after the class is archived (next to "Restore class").
    Cause: the Delete section sat outside the {% if course.archived_at %}
    block in edit.html.
  - Settings tab: an empty bordered box appeared under "Assign TA" when the
    class had students but no TA. The TA list now renders only once a TA
    exists; otherwise a plain "No TAs assigned yet." line is shown.

Editing announcement files (forms.py, views/posts.py, _post_card.html,
course.js)
  - Before: the edit form took one file only, any upload replaced ALL old
    files, and the X on one file removed all or none of them.
  - Now: each file's X removes only that file (sent as
    remove_attachment_ids, limited to this post's own attachments); several
    files can be added in one save and are added to the files kept.
  - Limit of 10 files / 25 MB now counts kept + new files.
  - Every new Material is announced (was: only the last one).
  - API compatible: remove_attachment=true still removes every file.

File guardrails on edit (course-tabs.js, _post_card.html, views/posts.py)
  - The server already rejected .exe/.bat/disguised executables on edit,
    but the edit form had no file-type filter or client-side check, and a
    rejected edit showed its error inside the New announcement form.
  - Now the edit form uses the same checks as create: accept filter,
    extension whitelist/blacklist, 25 MB / 10-file checks, Save blocked on
    error. A rejected edit shows "Failed to update announcement." with the
    reason at the top of the page.

Deadline notification on edit (views/posts.py)
  - Changing a deadline while editing never sent a notification: the old
    deadline was read after form.is_valid(), which had already copied the
    new deadline onto the post. It is now read before validation.

Principles (Lec #11 / #12)
  - DRY: the edit form reuses the create form's validation script instead of
    a second copy of the rules.
  - Security (quality dimension 9): input validation on both client and
    server; attachment ids are checked against the post being edited.
  - SRP: which attachments to remove and the file limits live in the form
    (removed_attachments, _check_file_limits); the view only saves.
  - Readability / complexity: the limit check was split after it first
    scored CC C (11); the new form methods are now A or B.
